# Media providers

Search defaults to **All providers** and starts Deezer, Lossless.am and Hitmo searches concurrently. Results appear as each source responds and are ranked together by query relevance, regardless of provider. Ranking favors title/artist matches over album-only matches, normalizes punctuation and accents, and demotes unrequested live/remix/cover versions. The provider selector uses accessible tabs with an explicit selected state. An unavailable provider shows a warning without hiding results from the others; routine capability notices are omitted. The provider selector is saved in the URL (`provider=all`, `provider=deezer`, `provider=hitmo` or `provider=lossless`). Direct song/album links in All providers mode are sent only to their own provider. The API retains its legacy Deezer default for clients that omit the provider parameter. Each song request has a provider identity; Deezer targets retain their existing `deezer:track:<id>` format. Lossless.am uses `lossless:track:<source>:<id>`, including the source returned by the service. IDs from different catalogs cannot fulfill each other's requests.

The `mediaProvider` interface in `internal/app/providers.go` covers search, recording revalidation, readiness and acquisition. Approval, quality snapshots, library reuse, validation, placement and Navidrome publication are shared. Deezer and Lossless.am album adapters resolve provider-specific track lists into shared album snapshots, approvals and progress. Import review and automatic matching search configured music providers. Deezer and lossless.am candidates retain independent source identities in review, ranking and requests. New adapters must return normalized `Track` metadata with a stable provider identity and implement these operations.

## Lossless.am (experimental)

Provider operations follow the supplied HARs and the provider’s client:

- `POST /api/search` with a JSON `query`.
- `GET /api/download/track?id=…&source=…`, returning FLAC.
- `GET /api/album/<id>?source=<source>` for album metadata and the ordered track list.
- Song and album search and requests, including existing approval and retry/review flows.

Choose **lossless.am** in Search. The download endpoint returns the best original available to the configured account. ZenSync probes the file instead of relying on its MIME label, keeps FLAC, MP3 or AAC without transcoding, and records its actual codec/bitrate. Enable lower qualities to allow lossy fallback; a FLAC-only profile still rejects lossy audio. Enabled lossy tiers set the minimum accepted native bitrate, so a 192 kbps original can satisfy an enabled 128 kbps fallback without re-encoding it. Album results are included in keyword search. Choose **View tracks** to inspect and listen, or **Request album** to submit the full album. Direct `https://lossless.am/app/album/<source>/<id>` and `https://lossless.am/app/album/<id>?source=<source>` links also work. The adapter uses the observed `GET /api/album/<id>?source=<source>` contract and normalizes its album metadata and ordered tracks.

Full albums use one approval and a frozen track/quality snapshot. Approved children retain `lossless:track:<source>:<id>` identities and run through normal exact-recording revalidation, acquisition and library reuse. Per-track progress is grouped under the album request; retrying a failed album only requeues failed tracks. Album identities are `lossless:album:<source>:<id>`, preserving opaque and leading-zero IDs in `sourceId`; Deezer album identities keep their existing numeric form. IDs from different providers or catalogs cannot share request state. Empty, incomplete, duplicate or mismatched album track lists fail before a request is saved. Track lists are limited to 5,000 recordings. These paths are covered by local provider fixtures and browser regressions; live authenticated album acquisition remains unverified.

 Lossless.am and Deezer recordings can be streamed in full in Search and import review. Import review searches lossless.am when configured, accepts direct `https://lossless.am/app/track/<source>/<id>` links, and supports both individual and bulk acquisition. Automatic matching uses the same conservative metadata checks across configured providers.

An administrator can enter their lossless.am email/password under **Settings → Music providers → Lossless.am**. Once both fields are valid, ZenSync signs in with `POST /api/auth/login`, verifies `/api/me`, and saves the returned session cookies in the encrypted credential store. The password is used only for sign-in and is never stored. A failed login leaves the previous connection intact.

The observed login response sets a 24-hour `jwt_access` cookie at `/` and a 90-day `jwt_refresh` cookie at `/api/auth`. ZenSync respects cookie paths and expiry, so refresh credentials are not sent to search or download endpoints. On HTTP 401 it attempts `POST /api/auth/refresh`, saves rotated cookies and retries the original request once. Device-bound refresh JWTs supply the `device_id` hint observed in the site's client code; login tokens without a device ID use an empty JSON object. Refreshes and connection replacement are serialized to avoid overwriting a newer session. Once refresh expires or is revoked, sign in again; ZenSync does not retain a password for automatic re-login.

The settings UI uses email/password sign-in only. Existing manually configured cookie sessions continue to work and can renew access when they include a refresh cookie. HTTP failures log the endpoint, status and timing without exposing credentials or response bodies. Sign-in errors distinguish login from account verification, and HTTP 451 points to provider or network access restrictions on the ZenSync server. Redirects are rejected to avoid forwarding sessions to another host.

The captured client establishes `GET /api/track/<id>?source=<source>` for exact lookup. Pasted links and worker revalidation require the returned source/ID to match the selected recording. Execution also compares current metadata against the approved snapshot. Downloads use bounded staging (1 GiB), audio response checks, measured codec/bitrate and tag/ISRC/duration verification and full decoding before placement. Lossless.am does not have Deezer's documented `SOURCEID` tag contract, so its files are checked using the selected endpoint identity and recording metadata. Deezer retains its mandatory source-ID check. A duration discrepancy uses the existing explicit retained-audio review.

Validation uses a local API fixture and generated FLAC audio, including password sign-in, cookie paths/expiry, refresh rotation and concurrent requests. The login request and Set-Cookie contract were supplied separately; the refresh request was found in the captured client code. Live requests with Go’s default user agent returned HTTP 451 on November 4, 2026. Repeating login (with deliberately invalid credentials) and account lookup using a browser-compatible user agent returned the expected HTTP 401. The adapter now uses that user agent; live password sign-in, token renewal, a real authenticated download and the service's actual output tags remain unverified. Files whose tags do not match the selected recording fail validation and are not published.

## Streaming and recording review

The listening player stays fixed at the bottom of the viewport in Search and recording review, including on narrow screens. It supports play/pause, seeking, volume, mute and dismissal. Closing the player or review stops playback. Listening never submits an acquisition request and is independent of the download quality profile.

Deezer full-song playback uses the saved Deezer ARL and the pinned d-fi binary, requesting **128 kbps** with quality/recording fallback disabled. The selected recording's tags, source ID, duration and encoding are validated before playback. This prepares a temporary buffer before audio starts, so Deezer can have a short startup delay. Buffers are limited to 32 MiB each and four concurrent sessions, keyed by user, recording, playback session and credential fingerprint. They are reused for seeking, expire from reuse after five minutes and are evicted as new sessions arrive. Temporary audio and configuration are removed after preparation; nothing is placed in the music library or published to Navidrome. Full playback requires a working Deezer connection and account access. Tests exercise the downloader boundary with generated MP3; live authenticated Deezer streaming remains unverified.

Import review presents one provider-results list ranked across all configured providers using the existing recording comparison rules. Each row identifies its source. The All sources, Deezer and Lossless.am quick filters preserve the ranked order and are saved in the URL without refetching candidates. Existing Navidrome recordings remain separate because they can be reused without acquisition.

Lossless.am playback uses the captured `POST /api/stream/token` and `GET /api/stream/track` contract. ZenSync obtains tokens on the server and proxies audio through an authenticated local endpoint. Browser requests contain the selected recording identity and playback session, never the provider JWT, session cookies or stream token. A rejected stream token is renewed once. Single byte ranges, partial responses and unsatisfiable ranges are supported for seeking. Playback does not create an acquisition request or publish a library file; closing the review stops playback.

Lossless.am requests the provider's cellular streaming route (`_net=cellular`) rather than Wi-Fi to favor its lower-bandwidth profile. The service chooses the actual encoding according to its account/device settings; no unsupported bitrate parameter is invented and account settings are not rewritten. Streams retain the codec supplied by the service, including MP4-wrapped audio observed in the HAR. Playback therefore depends on the browser's codec support and the configured account's access. Streaming quality is separate from the quality validation applied to downloaded library assets. Tests use a simulated provider plus generated browser-playable audio; live authenticated streaming remains unverified.

## Hitmo (experimental)

Choose **Hitmo** in Search to search `https://eu.hitmoz.com/` by song or artist, or paste a direct `https://eu.hitmoz.com/song/<id>` link. No account or credentials are required. Individual requests use stable `hitmo:track:<id>` identities and the normal approval, retry, download progress, validation and Navidrome publication flow. Direct Hitmo song links also work in import recording review; Hitmo is not searched automatically during import matching.

The adapter reads the public `/search?q=…` and `/song/<id>` HTML pages, using the site's embedded recording metadata and full MP3 download link. The exact song page is fetched again before acquisition. Page-supplied external audio URLs are rejected. Full MP3 downloads may follow one HTTPS redirect to the observed `cdn<number>.deliciousoranges.com` and `s<number>.deliciouspeaches.com` delivery hosts, preserving the selected file path with its observed optional `/s1` prefix; other destinations and redirect chains are rejected. The page structure can change; this integration has no documented API stability guarantee.

Listening prefers the site's 128 kbps `data-musmeta.url` under `/get/cuts/` when offered and otherwise uses the full MP3 URL. Acquisition continues to use the original download link. Hitmo supplies MP3, not FLAC. Enable **320** or **128** in the requester's quality preferences to accept lossy originals. Files keep their native bitrate without transcoding; a FLAC-only profile rejects MP3. Full-song listening is available in Search and import recording review before making a request, with play/pause and seeking. Audio is proxied through an authenticated ZenSync endpoint; listening does not create a request, require approval or add a file to the library. Album browsing and grouped album acquisition are unavailable; this does not refer to cover artwork. Available Hitmo artwork is shown in the player. Hitmo does not supply album or ISRC metadata, so revalidation compares the approved provider identity, title, artist and duration; downloaded audio must have matching title/artist tags, acceptable measured codec/bitrate and duration, and pass full decoding. No album or ISRC is invented. Missing or mismatched title/artist tags fail validation.

Tests cover HTML parsing, URL restrictions, request identity, revalidation, rejected redirects/non-audio downloads, quality restrictions, validated MP3 placement, streaming byte ranges and listening without acquisition. Browser tests cover playback beyond 30 seconds and cleanup on closing recording review. A live search, exact song lookup, full MP3 acquisition and streaming byte range for the reported OG Buda recording (`78334571`, via `s3.deliciouspeaches.com`) were checked on November 13, 2026. To repeat the optional live smoke test: `ZENSYNC_TEST_HITMO_LIVE=1 go test ./internal/app -run '^TestHitmoLive$' -v`. End-to-end publication against a live Navidrome server remains unverified.
